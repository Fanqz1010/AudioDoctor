# Audio Doctor 使用说明

## 这是什么

Audio Doctor 是一个 Mac 桌面应用，用来给音频做「体检」、音乐结构标注和轻量修复，特别适合检查 Suno 等 AI 生成音乐里常见的高频沙沙声、频段偏薄、响度不一致和相位风险。v0.5 将单文件标注拆成「内容判断、音乐结构、技术质量、时间定位、标确切认」五个固定大类，并可递归处理上千个音频、导出客观标注报告。

它不是 DAW 插件，而是独立 app。原始音频不会被覆盖，处理结果会另存为新文件。

## 第一次打开

1. 解压 `AudioDoctor.app.zip`。
2. 把 `AudioDoctor.app` 拖到「应用程序」或任意固定位置。
3. 双击打开。如果 macOS 提示无法验证开发者，请右键点 App，选择「打开」，再点一次「打开」。
4. 系统版本要求：macOS 13 或更高。

## 基本流程

### 1. 标注工作台与音频体检

把 WAV / AIFF / M4A / MP3 拖到左侧「拖入待标注音频」。应用先判断内容类型，再进入五个固定大类：

1. **内容判断**：是否音乐、纯音乐 / 带人声、置信度和依据。
2. **音乐结构**：调性、转调、BPM、拍号变化、和弦功能、配器角色。
3. **技术质量**：响度、真峰、削波、相位、空间、AI 伪影。
4. **时间定位**：按秒定位可疑区间。
5. **标确切认**：汇总自动等级、异常项、复核项和处理建议。

主要技术指标包括：

- **综合响度 LUFS**：流媒体常用 `-14 LUFS` 附近； Podcast 常用 `-16` 左右。
- **真峰 dBTP**：建议不超过 `-1 dBTP`，否则有削波或转码失真风险。
- **失真风险**：基于削波采样、样本峰值和超采样峰值估算。
- **相位相关性**：`1` 附近表示左右声道很接近；接近 `0` 表示很宽但单声道兼容风险高；负数表示明显反相。
- **立体声宽度**：由 mid/side 能量估算。
- **疑似 AI 感**：启发式评分，结合低频/身体感不足和高频噪声占比。它不是标准听感评分，只做提示。

### 2. 导入参考曲（可选，但推荐）

把一首你觉得「丰满、真实」的歌拖到「参考曲」区域。应用会显示两者频段能量差距。处理时勾选「使用参考曲频响匹配」，目标音频会向参考曲的频段平衡靠拢。

参考曲应选同类编曲、同类混音风格。不要用完全不同风格的歌曲做强匹配。

### 3. 一键转换

- 立体声 → 单声道：左右取平均。
- 单声道 → 立体声：复制到左右声道。
- 立体声 → 5.1 环绕声：输出 6 声道 `L、R、C、LFE、Ls、Rs`。
- 立体声 → AmbiX 全景声：输出一阶 Ambisonics 4 声道 `W、Y、Z、X`，使用 ACN 排序和 SN3D 归一化。

如果相位相关性很低或为负，转单声道前一定要试听，可能出现抵消。

#### 空间音频转换说明

**5.1 环绕声**采用保守矩阵：

- 左右前声道尽量保留原始立体声。
- 中置来自左右的中置成分，并做轻度频带限制，避免人声糊。
- LFE 来自 120Hz 以下的低通信号。
- 环绕声道来自左右差信号，带延迟和频带限制；接近单声道的素材会自动补一点很低的氛围感，避免环绕完全无声。

**AmbiX** 是开源空间音频生态里常用的交换方式，不等同于 Dolby Atmos 母版。它适合后续交给支持 Ambisonics 的播放器、游戏引擎、VR/AR 或空间音频插件继续渲染。如果你的目标是在 Mac 上确认声道元数据，AIFF/AIF-C 导出会在系统信息中显示 `High-Order Ambisonics, ACN/SN3D`。

空间格式导出后，界面右侧的响度与相位指标仍基于修复后的立体声源显示。这是因为 AmbiX 的 `W/Y/Z/X` 不是普通扬声器信号，直接按左右声道相位解读会误导。

### 4. AI 音感修复

修复工作台与标注工作台共享同一个分析结果。标注页确认问题后，可点击「带诊断结果去修复」进入修复流程；修复页会用较友好的语言解释每项伪影对应的处理。

默认链路为：

1. 去高频沙沙声：高频包络控制的扩张处理。
2. 补足低频与身体感：内置温和 EQ，或参考曲频段匹配。
3. 增加细节与空气感：轻微高频谐波激励。
4. 响度标准化：默认 `-14 LUFS`。
5. 真峰限制：目标不超过 `-1 dBTP`。

第一次建议强度 `0.8–1.0`。如果鼓组发闷、人声变硬或出现呼吸感 pumping，降低强度或关闭某一步。

### 5. 导出

支持 WAV / AIFF，16-bit 或 24-bit。处理完成后会显示处理前后关键指标对比。

## 音乐结构分析

Audio Doctor 会在单文件分析中给出以下音乐结构参考：

1. **内容类型**：是否音乐、纯音乐 / 带人声、人声置信度和判断依据。
2. **调式调性**：主音、大调/小调、候选调性、置信度和十二音级能量分布。
3. **转调时间轴**：疑似转调段落、原调性、目标调性、时间范围和置信度。
4. **节拍**：BPM、每拍时长、估算拍数、Onset 密度与拍号参考。
5. **速度 / 拍号变化**：提示局部 BPM 或拍号与全曲不一致的区间。
6. **和弦功能**：近似输出和弦、级数、主功能 T / 下属与预属功能 S/PD / 属功能 D。
7. **配器角色**：根据频段、瞬态、持续度和立体声信息推测主奏、辅助、低频支撑、节奏基础、氛围/和声。

边界：这些是混合音频的启发式分析，不是源分离或自动记谱。配器无法保证精确识别真实乐器；和弦在复杂编曲、转调、低音不清时容易出错。低置信度时应由标注员人工确认。批量 CSV/HTML 报告也会输出内容类型、调性、转调 / 节拍变化、和弦功能、BPM、主奏推测与配器置信度。

## AI 伪影精修与时间轴定位

在「修复工作台」，Audio Doctor 会把过去一个笼统的「疑似 AI 感」拆成七个可解释指标：

| 指标 | 主要回答的问题 | 常见听感 |
| --- | --- | --- |
| 高频沙声 | 9kHz 以上能量是否异常偏高 | 沙沙声、嘶声、脏空气感 |
| 金属闪烁 | 高频能量与频谱平坦度是否异常 | 发硬、发金属、 shimmer |
| 频谱空洞 | 相邻频带是否有明显缺洞 | 不丰满、断档 |
| 频段偏薄 | 20–350Hz 身体感是否不足 | 薄、假、没低频支撑 |
| 相位不稳定 | 分窗相位相关是否波动 | 声像漂、低频不稳 |
| 瞬态模糊 | 包络攻击变化是否不足 | 鼓点糊、人声边界不干净 |
| 立体声异常 | 左右平衡、折叠损失、低相关风险 | 偏边、单声道兼容差 |

时间轴 Badcase 会按窗口给出「开始秒–结束秒、问题、严重度、证据、建议」。标注员不要只看总分，应优先试听高严重度区间，再结合整首内容做判断。

### 修复链路

1. 高频稳态伪影抑制
2. 低频与身体感补偿，或参考曲带状匹配
3. 125Hz 以下低频单声道化，降低相位抵消
4. 包络跟随瞬态恢复，只增强攻击段
5. 谨慎空气感增强；若高频噪声仍高会自动减弱
6. 响度标准化与 -1 dBTP 真峰限制

### 内容优化预设

「内容优化导出」工作台提供通用音乐、Suno 人声、Suno 流行、电子/舞曲、影视/配乐、播客/口播预设。预设会影响低频、中频、高频、空气感、瞬态恢复量和低频单声道化比例，但仍建议先小样本 A/B，不要整批直接强处理。

## 千级批量标注中心

### 界面切换

顶部工作台分为「标注工作台」「修复工作台」「批量标注」「内容优化」。

主界面右上角可以切换：

- **标注工作台**：用于一个音频的内容判断、音乐结构、技术质量、时间定位和人工确认。
- **修复工作台**：用于根据诊断结果微调参数、修复和导出。
- **批量标注中心**：用于几十、几百、上千个音频的队列处理和 CSV 报告。

两个工作台互相独立，批量处理有自己的一套修复参数，不会误改单文件设置。

### 批量流程

1. 把音频文件夹拖入批量输入区，或点击「选择输入」。
2. App 会递归扫描 WAV / AIFF / M4A / MP3 / FLAC / CAF。
3. 选择输出文件夹。输出文件夹不要放在输入文件夹里面。
4. 选择模式：
   - **只分析 / 标注报告**：不修改音频，只生成 CSV，适合标注前质检。
   - **修复并导出**：执行修复链并输出新文件。
5. 点击「开始批量处理」。
6. 查看成功 / 失败 / 跳过数量。
7. 打开 CSV 报告，按 A / B / C / D 等级分派任务。

### 报告

每次批量会生成两个文件：

- CSV：全量技术明细，适合导入表格和标注平台。
- HTML：批次总结，包含等级分布、集中问题、优先复核文件和处理建议。

### 千级任务设计

- 顺序队列处理，避免同时打开上千个音频导致内存爆炸。
- CSV 每处理完一个文件就写入一行，中途取消也不会丢掉已完成记录。
- 默认跳过已经存在的输出文件，中断后重新运行相当于续跑。
- 失败文件不会中断整个队列，会在结果中标明错误。
- 保留原始目录结构，输出文件不会覆盖原音频。

### 标注等级

| 等级 | 含义 | 建议 |
|---|---|---|
| A | 客观指标通过 | 可直接标注 |
| B | 个别边界风险 | 可标注，写复核备注 |
| C | 多项边界风险 | 技术复核后标注 |
| D | 明显技术异常 | 先修复或退回 |

详细标准见仓库中的 `docs/annotation-standards-zh.md`。

## 当前限制

- `web/index.html` 当前是跨平台界面基础稿，尚未接入本地分析引擎。
- Windows 版尚未打包；v0.5 先以 Web 界面基础稿确定跨平台信息架构。

- 输出暂不支持 MP3/AAC，推荐先用 24-bit WAV 保留质量。
- 第一版空间转换为保守离线矩阵，不含神经网络分离，也不会“猜出”真实分轨；效果取决于原立体声的宽度与信息量。
- AmbiX 输出不等于 Dolby Atmos。制作正式 Dolby Atmos 母版通常需要专用授权工具链、对象/床 metadata 和认证流程。
- 尚未内置神经网络修复模型；当前是无 AI 依赖的轻量信号处理链。
- 「疑似 AI 感」不是客观听感的最终判决，必须以实际试听为准。
- 批量第一版为顺序队列，尚未提供多线程并发配置。
- AmbiX / 空间指标用于客观提示，不能替代专业声学评价。
- 参考曲匹配会改变音色，强匹配可能削弱原曲个性。

## 推荐的 Suno 音频处理流程

1. 先直接分析，看高频噪声占比、低频能量和相位。
2. 导入一首同类真人混音参考曲。
3. 强度从 `0.8` 开始。
4. 勾选：去沙声、补低频、参考曲匹配、空气感、响度标准化。
5. 导出 24-bit WAV。
6. 对比原始文件和处理文件；如果处理感重，降低强度或关闭空气感。
